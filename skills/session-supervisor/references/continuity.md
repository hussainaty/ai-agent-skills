# Codex and Claude continuity

Use the existing working notebook as the primary running state; do not maintain a second transcript. At a material checkpoint, an explicit handoff request, or an observed impending limit that could interrupt unfinished work, save a short continuation package. Do not assume either host exposes remaining context, quota, reset time, or an imminent stop; distinguish observed values from estimates and say when unavailable. Continue useful bounded work while possible, and do not mark an incomplete task complete just because a session stopped.

## Checkpoint

1. Finish or safely stop the current atomic operation. Record in-flight jobs and whether they may still write; a wait timeout is not cancellation. Preserve unfinished changes and avoid starting a conflicting writer.
2. Update and accept the existing notebook. In a private, access-controlled project state directory, create or update `AI_CONTINUATION_CONTEXT.md` and, for the intended recipient, `CLAUDE_CONTINUATION_PROMPT.md` or `CODEX_CONTINUATION_PROMPT.md`. Prefer an existing private notebook directory; verify ignore rules before writing task-specific data inside a repository. Never commit or publish these files without authorization. Exclude secrets, credentials, full transcripts, and unnecessary personal information. Do not overwrite a different task's handoff.
3. Keep the context concise and source facts. Include the objective, applicable user requirements and decisions, project/worktree and branch, relevant paths and architecture, exact Git status and changed files, completed and pending work, invariants, known failures and ruled-out hypotheses, actual test commands and results, outstanding blockers and worker-job state, and the single next action. Include research links only when useful. Note unknowns explicitly. Update on meaningful changes, not every small edit.
4. The recipient prompt should say: read `AI_CONTINUATION_CONTEXT.md`; inspect Git status, actual diff, relevant tests and any active job; verify the handoff against current repository evidence; preserve settled decisions; resume the highest-priority unfinished work with selective skills and focused verification; update the handoff on meaningful changes. When handing to Claude, request the same preparation for a return handoff if an observable limit makes completion unlikely.
5. Verify that the handoff files exist and report their location and any blockers. To avoid duplicate work, start or message another agent only through a supported host action and within the user's authorization, after checking the existing worker's state. If the receiving agent, authentication, quota, dispatcher, or shared filesystem is unavailable, leave a usable manual handoff and report that automatic continuation is not connected.

If the task is registered with the [relay](relay.md), write `relay-signal.json` after the handoff files; the relay then starts the recipient automatically. Otherwise, preparing a handoff does not transfer or start a session. A skill cannot guarantee a pre-expiry warning or monitor a stopped process. The separately documented Codex wake scheduler is not an active dispatcher, and Claude's native limit behavior must be verified in the actual environment rather than assumed.
